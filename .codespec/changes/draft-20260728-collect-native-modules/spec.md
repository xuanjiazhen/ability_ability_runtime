## 用户故事

### US-1: 启动阶段采集 Native 模块落盘

**作为** 系统开发者，
**我想要** 应用启动时自动采集本进程 fork 后显式 import 的 Native 模块并写入应用沙箱 cacheDir，
**以便** 获得模块依赖事实数据。

**验收标准（AC）：**

| AC编号 | 验收标准 | 类型 |
|--------|----------|------|
| AC-1.1 | WHEN 应用启动且采集开关开启 THEN 启动阶段结束后应将本轮 fork 后显式 import 的 Native 模块合并写入沙箱文件，且每轮启动写盘不超过 1 次 | 正常 |
| AC-1.2 | WHEN 采集开关未下发或缺失 THEN 应缺省关闭：不采样、不读取、不写入任何文件，启动行为与未集成该特性时完全一致 | 正常 |
| AC-1.3 | WHEN 应用存在多个进程 THEN 各进程应写入各自独立的沙箱文件，文件名互不相同、互不覆盖 | 边界 |
| AC-1.4 | WHEN 写盘过程发生 I/O 失败 THEN 正式文件应保持写前状态或不存在，不得出现内容残缺的文件 | 异常 |
| AC-1.5 | WHEN 进程模块链表中含 fork 前预加载（preload）阶段加载的模块 THEN 采集结果不得包含这些模块 | 边界 |

### US-2: 跨启动更新并预测下轮模块集

**作为** 系统开发者，
**我想要** 沙箱文件按跨启动策略自我更新并输出下轮启动预测模块集，
**以便** 数据可直接用于启动优化且长期保持准确。

**验收标准（AC）：**

| AC编号 | 验收标准 | 类型 |
|--------|----------|------|
| AC-2.1 | WHEN 模块在连续多轮启动中均被应用显式 import THEN 其评分应单调收敛趋近 1 并稳定出现在预测集中 | 正常 |
| AC-2.2 | WHEN 模块连续 16 轮启动未被加载或其评分衰减低于 0.05 THEN 该模块条目应从文件中淘汰 | 边界 |
| AC-2.3 | WHEN 沙箱文件内容损坏、格式版本不符或被系统缓存清理删除 THEN 应按冷启动规则重建文件，不抛错、不影响启动 | 恢复 |
| AC-2.4 | WHEN 应用版本升级（appVersionCode 变化）后首次启动 THEN 应清空历史评分按冷启动规则重建 | 恢复 |
| AC-2.5 | WHEN 消费方在本轮启动预加载了某模块而应用未显式 import 它 THEN 该模块不得计为本轮命中（评分不得因此上升） | 边界 |

### US-3: 启动框架预加载预测的系统 so

**作为** 系统开发者，
**我想要** 启动框架在启动早期读取预测集并预加载其中的系统模块，
**以便** 缩短应用真实 import 时的加载耗时。

**验收标准（AC）：**

| AC编号 | 验收标准 | 类型 |
|--------|----------|------|
| AC-3.1 | WHEN 启动早期且沙箱文件存在且采集开关开启 THEN 启动框架应读取预测集中的系统模块（isAppModule=false）并触发预加载 | 正常 |
| AC-3.2 | WHEN 沙箱文件缺失、损坏或格式版本不符 THEN 应跳过本轮预加载且启动流程不受影响 | 异常 |
| AC-3.3 | WHEN 预测集中某一系统模块预加载失败 THEN 应记录故障事件、继续其余模块的预加载，且不影响启动流程 | 异常 |
| AC-3.4 | WHEN 沙箱文件预测集中不含任何系统模块 THEN 应不触发任何预加载动作 | 边界 |

### US-4: 与应用沙箱文件无感共存

**作为** 应用开发者，
**我想要** 系统采集文件不与我的沙箱文件混淆、不可见、不侵犯隐私，
**以便** 我的应用无需任何适配即可共存。

**验收标准（AC）：**

| AC编号 | 验收标准 | 类型 |
|--------|----------|------|
| AC-4.1 | WHEN 采集文件写入沙箱 THEN 其应位于点前缀隐藏的系统托管目录内，文件名含系统命名空间与格式版本标识，与开发者常见文件命名不冲突 | 正常 |
| AC-4.2 | WHEN 采集文件生成 THEN 文件权限应为 0600，内容仅含模块名/路径/版本/统计计数等公开信息，不含用户数据 | 正常 |

## 规则定义

| 规则ID | 类型 | 触发条件 | 预期行为 | 边界/约束 | 关联AC |
|--------|------|----------|----------|-----------|--------|
| R-1 | 行为 | 开关开启，应用启动完成启动阶段（双检查点采样完成） | 本轮采集集合合并历史评分后写入沙箱文件；每轮启动写盘 ≤1 次；写盘不占用主线程 | 文件大小稳态 < 100KB | AC-1.1 |
| R-2 | 行为 | 开关参数未下发/缺失/显式关闭 | 全程零文件 I/O、零采样；启动行为与存量一致 | 开关判定结果本轮启动内缓存，不重复读参 | AC-1.2 |
| R-3 | 行为 | 一轮启动完成，模块 m 本轮被显式 import（命中） | 文件中 m 的评分按 score ← α + (1−α)·score 更新（α=0.4）；连续命中时单调趋近 1 | α 支持系统参数调优，缺省 0.4 | AC-2.1 |
| R-4 | 行为 | 写盘时计算预测集 | predicted = { m \| score ≥ 0.5 }，预计算后随文件输出 | 阈值 0.5 支持系统参数调优 | AC-2.1 |
| R-5 | 边界 | 模块连续 16 轮未命中，或更新后 score < 0.05 | 条目从文件中移除 | 淘汰在写盘前执行 | AC-2.2 |
| R-6 | 边界 | 历史条目数超过 1024 | 按 score 升序淘汰至 1024 条以内 | 上限 1024 为硬约束 | AC-2.2 |
| R-7 | 恢复 | 文件 JSON 解析失败、version 字段不符、或文件被缓存清理删除 | 丢弃旧数据，按冷启动规则（首轮命中 score=1 全量入预测集）重建；不抛错、不影响启动 | 重建发生在本轮检查点写盘时 | AC-2.3, AC-3.2 |
| R-8 | 恢复 | appVersionCode 与文件记录不一致 | 清空全部历史评分，按冷启动规则重建 | 升级判定以 appVersionCode 为准 | AC-2.4 |
| R-9 | 边界 | 模块本轮由消费方预加载且应用未显式 import | 不计为本轮命中（评分不上升，也不按遗漏衰减——本轮对该模块不更新） | 区分依据为实现侧加载计数，见 design.md | AC-2.5 |
| R-10 | 行为 | 启动早期、开关开启、文件存在且格式合法 | 读取 predicted 中 isAppModule=false 的模块并触发预加载；predicted 无系统模块时不动作 | 预加载在非主线程执行 | AC-3.1, AC-3.2, AC-3.4 |
| R-11 | 边界 | 采集文件写入 | 路径为 cacheDir 下点前缀隐藏系统目录；文件名含系统命名空间、进程名哈希（8 字符）与格式版本后缀；权限 0600 | 各进程哈希不同则文件名不同 | AC-1.3, AC-4.1, AC-4.2 |
| R-12 | 边界 | 模块在 fork 前 preload 阶段已加载 | 不出现在采集集合与预测集中 | 区分依据为 fork 前快照，见 design.md | AC-1.5 |
| R-13 | 异常 | 写盘 I/O 失败（含写临时文件失败、rename 失败） | 正式文件保持写前状态或不存在；记录故障事件 | 不允许出现残缺正式文件 | AC-1.4 |
| R-14 | 异常 | 预测集中某系统模块预加载失败（so 缺失/加载错误） | 记录故障事件（含模块名与错误信息），继续其余模块，启动流程正常推进 | 单模块失败不阻断 | AC-3.3 |

## 接口规格

### 接口定义

**GetLoadedModuleInfos**

| 属性 | 值 |
|------|-----|
| 函数签名 | `void GetLoadedModuleInfos(std::vector<NativeModuleInfo>& infos)` |
| 返回值 | void — 结果经出参 `infos` 返回 |
| 开放范围 | InnerApi |
| 错误码 | N/A（不报错；空结果返回空列表） |
| 关联 AC | AC-1.1, AC-1.5, AC-2.5 |

**参数约束**

| 参数 | 类型 | 必填 | 默认值 | 约束条件 |
|------|------|------|--------|---------|
| infos | `std::vector<NativeModuleInfo>&` | 是 | 无 | 调用前不要求为空；实现不得残留旧数据（先清空再填充） |

**行为场景**

| # | 触发条件 | 预期行为 | 关联 AC |
|---|----------|----------|---------|
| 1 | 进程已加载 ≥1 个 Native 模块 | 返回全部已加载模块的快照，字段与模块管理器内部记录一致（深拷贝，与内部节点生命周期无关） | AC-1.1 |
| 2 | 进程未加载任何模块 | 返回空列表，不报错 | AC-1.1 |
| 3 | 多线程并发调用（含与模块加载并发） | 返回一致性的快照（要么含某模块要么不含，不出现字段撕裂） | AC-1.1 |
| 4 | 快照返回后原模块被卸载 | 已返回的快照数据保持有效 | AC-1.1 |

## 兼容性声明

- **已有 API 行为变更:** 否。无 Public/System API 变更；模块加载路径行为不变。
- **配置文件格式变更:** 否。不改动任何既有配置文件；开关为新增系统参数，缺省关闭。
- **数据存储格式变更:** 是（新增）。沙箱采集文件为本特性新增，格式自带 version 字段；version 不符或解析失败时按 R-7 丢弃重建，不存在旧版本迁移问题。
- **最低支持版本:** 引用 proposal.target_release（OpenHarmony-7.1-Release）。
- **API 版本号策略:** InnerAPI 不提供 @since 标注；跨仓编译期对齐（两仓同版本合入）。

## 架构约束

| 关键约束 | 约束说明 | 影响 AC |
|----------|----------|---------|
| 仅写应用自身沙箱 | 采集文件只允许写入本进程应用沙箱 cacheDir，禁止跨应用/跨用户写入 | AC-1.1, AC-4.1, AC-4.2 |
| 加载路径零侵入 | 不得修改模块注册/加载/查找的既有行为；采集只能是旁路读取 | AC-1.2 |
| 开关门控缺省关闭 | 系统参数未下发时缺省关闭；开启判定结果本轮启动内缓存 | AC-1.2 |
| 失败不影响启动 | 采集、写盘、预加载任一环节失败均不得阻断或延迟应用启动主路径 | AC-1.4, AC-3.2, AC-3.3 |
