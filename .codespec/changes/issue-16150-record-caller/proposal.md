# Proposal

## 背景与问题

**动机**：上层框架和底层终止应用接口缺少调用方归因信息，无法在大数据统计中进行二级拆解分类。

**问题陈述**：
- 终止应用接口仅记录终止原因，不记录调用方 pid 和 processName
- 开发者无法判断是哪个系统服务或进程发起的终止
- 跨层定界困难，无法按调用方维度进行二级拆解分类

**当前痛点**：
- 应用被终止后，开发者无法定位是哪个系统组件发起的终止
- 大数据统计分析时，无法按调用方维度拆解终止事件

## 用户场景与业务触发

### US-1: 应用终止来源归因
- **角色**：应用开发者 / 可靠性维护人员 / 大数据分析平台
- **业务触发**：应用被系统组件终止（内存清理、异常处理、维护命令等）后，需要定位终止发起方
- **业务价值**：能够定位是哪个系统组件发起的终止，支撑大数据按调用方维度进行二级拆解分类，提升故障定界效率

## 目标

1. KillAppWithReason、KillBundleWithReason、RecordAppWithReason 三个接口被调用时，自动记录调用方 pid 和 processName（processName 可能为空），写入应用终止原因数据。
2. 调用方 pid 通过 IPC 调用上下文自动获取，无需调用方配合修改；进程名按 pid 反查。
3. 已记录的调用方信息可用于归因"哪个系统组件发起的终止"，支撑大数据按调用方维度二级拆解分类。

## 非目标

- 不修改三个终止/记录接口的签名与调用方式（自动获取方式无需调用方配合适配）。
- 不新增对外（public/system）API 暴露调用方信息，记录信息仅用于内部维测与大数据分析。
- 不实现上层大数据分类消费逻辑（不在本期范围）。

## 成功标准

> 每条标准写**系统级能力达成**（可观察、可量化）。**禁内部实现** + **禁接口细节**。

| 标准 | 可观察指标 | 验证方式 |

## 假设与开放问题

### 假设
- IPC 框架可可靠获取调用方 pid（服务侧调用上下文提供），无需调用方传参配合。
- processName 允许为空：进程信息反查不到时（如进程已退出）仅记录 pid，不影响主记录流程。
- 记录调用方信息的过程为容错设计，获取失败不阻塞终止主流程。

### 开放问题
- 多线程/并发调用场景下调用方 pid 的准确性需验证。
- processName 的获取时机（IPC 入口即时反查，还是读取时延迟解析）在 design 阶段确定。
- 上层大数据消费侧是否需要适配及所在仓库不在本期范围，如有需要另行立项。

## 资源开销审视

> 三维状态：`required` / `review-required` / `not-applicable` / `waived`。测量、预算与证据 schema 由子系统 `odk_resource_gate` 负责。
> 存储(ROM) 主语：交付进 OS 版本镜像的产物 + 运行后 data 分区下的大体量持久化；阈值归子系统 gate。

## 不涉及项确认

> 逐维度主动判断"涉及/不涉及"并填写依据；不允许留空；标"不涉及"必须写明理由。
> 「性能」行为摘要（过渡字段，后续以「资源开销审视」为准并废弃本行独立语义）：只由上方「性能」状态推导——`required` / `review-required` 为「是」，`not-applicable` / `waived` 为「否」；RAM/ROM 状态不改变本行语义。

| 维度 | 是否涉及 | 依据 |
|------|---------|------|
| 性能 | 否 | 性能状态为 not-applicable（低频维测路径，增量开销可忽略） |
| 安全/权限 | 是 | 变更位于终止接口的 IPC 服务入口，消费跨进程调用方身份（调用方 pid）并持久化调用方进程信息，跨信任边界处理归因数据 → design 阶段需产出安全基础检查 |
| 兼容性 | 是 | 终止原因持久化数据与 IPC 终止原因结构体新增字段，须保证存量持久化数据与既有调用方的向后兼容 |
| API/SDK | 否 | 不新增/修改公共或系统 API，interfaces/kits 无变更；三个接口为 inner_api 内部维测接口且签名不变 |
| IPC/跨进程 | 是 | 调用方 pid 取自 IPC 调用上下文；终止原因 IPC 结构体扩展涉及序列化兼容 |
| 构建/组件 | 否 | 无新增组件与构建目标，仅修改既有源文件 |
| 国际化/无障碍 | 否 | 后台维测功能，无 UI、无用户可见文本 |
| 数据迁移 | 否 | 无数据迁移；存量终止原因数据读取时按缺省空值兼容处理 |
