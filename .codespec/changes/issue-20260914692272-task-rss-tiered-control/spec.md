## 用户故事

### US-1: 单一受管上下文

**作为** 系统调度开发者，
**我想要** CLI 与 VIRTUAL_SCREEN_ABILITY 的纳管进程可以正确调度管控
**以便** 在 CLI 与 VIRTUAL_SCREEN_ABILITY 不叠加、单 Task 单次纳管的场景下准确核对代理日志和恢复过程，目前不对 ABILITY、A2A、INSIGHT 进行额外调度管控。

**验收标准（AC, Acceptance Criteria）：**

| AC编号 | 验收标准 | 可观察表面 | 类型 |
|--------|----------|--------------|------|
| AC-5.1 | WHEN 纳管进程发生新建、effectiveLevel 重算、 移除或死亡 THEN 实际调度管控日志仅包含创建者 pid/uid、纳管 pid/uid、受管工具、effectiveLevel、START/END 动作；CLI 与 VIRTUAL_SCREEN_ABILITY 不得叠加，ABILITY、A2A、INSIGHT 不产生调度管控； | InnerAPI（上下文日志） | 正常/边界 |

### US-2: 事件动作、固定窗口与最终生命周期

**作为** 系统调度开发者，
**我想要** 新建/升档和死亡立即输出事件，降档及非死亡结束按固定窗口合并，并保证最终生命周期和既有前端约束一致，
**以便** 在档位变化、最后移除、死亡和重新纳管时核对事件序列、最终状态及兼容性。

**验收标准（AC, Acceptance Criteria）：**

| AC编号 | 验收标准 | 可观察表面 | 类型 |
|--------|----------|--------------|------|
| AC-5.2 | WHEN 进程由未纳管变为纳管或 effectiveLevel 上升 THEN 在当前外部事件处理序列中直接输出包含最新状态的 START，不进入 1000ms 合并窗口；WHEN 纳管进程死亡 THEN 在当前死亡事件处理序列中直接输出 END，且该 pid 尚未输出的合并事件不再输出 | InnerAPI（代理事件序列） | 正常/异常 |
| AC-5.3 | WHEN effectiveLevel 下降，或主动注销、任务正常结束、任务超时、创建者死亡导致降档或最终结束 THEN 对应事件进入固定 1000ms 合并窗口且不读取系统参数；窗口内发生新建、升档、继续降档、任务结束或死亡时仅保留有效触发事件及到期时的最新唯一状态，无变化时不额外输出事件 | InnerAPI（代理事件及到期序列） | 正常/边界 |
| AC-5.4 | WHEN 最后一个受管 Task 或其唯一归因被移除 THEN 输出 END，最终 END 只结束当前生命周期，旧生命周期不得再输出后续 START/END；之后同一 pid 重新纳管时开启新生命周期并允许按 AC-5.2 立即 START；WHEN 纳管进程死亡 THEN 该 pid 仅输出一个最终 END，其他 pid 的事件不受影响；上述情况均不新增独立资源数量上限、超限拒绝或新错误码，既有前端任务与归因上限行为不变 | InnerAPI（代理事件及计数）/ System API（既有任务/归因结果） | 正常/异常/边界 |

## 规则定义

| 规则ID | 类型 | 触发条件 | 预期行为 | 边界/约束 | 关联AC |
|--------|------|----------|----------|-----------|--------|
| R-1 | 行为/边界 | 新建归属、effectiveLevel 重算、唯一受管 Task 上下文变化、最后移除或纳管进程死亡 | 上下文日志和实际代理事件仅包含当前唯一受管 Task 的 taskId、创建者 pid/uid、纳管 pid/uid、受管工具、变化前后 effectiveLevel、START/END 动作和触发原因；仅上下文变化且未进入开始/结束迁移时不增加代理事件，下一次实际事件使用最新唯一上下文 | 同一进程同一时刻仅允许一个受管 Task，同一 Task 对同一进程仅允许一次纳管；CLI 与 VIRTUAL_SCREEN_ABILITY 不叠加；ABILITY、A2A、INSIGHT 不参与计算或事件 | AC-5.1 |
| R-2 | 行为/异常 | 进程由未纳管变为纳管、effectiveLevel 上升，或纳管进程死亡 | 新建/升档直接输出 START；死亡直接输出 END；均不进入 1000ms 合并窗口，死亡同时使旧合并事件失效 | effectiveLevel 取 LOW(100)/MEDIUM(200)/HIGH(300)；死亡事件不影响其他 pid | AC-5.2 |
| R-3 | 行为/边界 | effectiveLevel 下降，或主动注销、任务正常结束、任务超时、创建者死亡导致降档或最终结束；窗口内再次发生新建、升档、继续降档、任务结束或死亡 | 降档及非死亡结束进入固定 1000ms 合并窗口，到期仅输出最新唯一状态；丢弃旧档位/旧受管上下文，无变化时不额外输出 | 窗口固定为 1000ms，不读取系统参数；不得把窗口内每次变化都作为独立事件排队输出 | AC-5.3 |
| R-4 | 行为/异常/边界 | 最后一个受管 Task 或其唯一归因被移除、最终 END 后重新纳管、纳管进程死亡，或既有前端任务与归因上限校验 | 最后移除时输出 END，最终 END 只结束当前生命周期，旧生命周期无后续 START/END；重新纳管开启新生命周期并允许立即 START；死亡 pid 只输出一个最终 END，其他 pid 不受影响；不新增独立配额、超限拒绝或错误码，既有前端上限行为不变 | 重新纳管不得复用旧生命周期状态；不取消、不提高、不降低既有前端任务与归因限制 | AC-5.4 |

## 验证映射

> 每个 AC 至少关联一个可执行的集成验证入口。本节仅呈现系统场景、集成接口和日志可观察结果；单元测试及其 Red/Green 过程归 design.md 内部闭环，不在本节展开。实现后的实际结果和证据由 execution-plan / Verification Evidence 回填。

| 编号 | 对应规格项 | 集成验证入口 | 验证方式 | Red 条件（实现前失败信号） | 通过标准 |
|------|------------|--------------|----------|---------------------------|----------|
| VM-1 | R-1 / AC-5.1 | 分别构造 CLI 与 VIRTUAL_SCREEN_ABILITY 的单 Task 单次纳管、上下文不变档变化、最后移除及死亡场景，并叠加 ABILITY/A2A/INSIGHT 变化 | 集成：唯一受管上下文、事件计数、动作和原因核对 | 旧版本以多 Task、多工具组合验证，无法证明单 Task 单次纳管时字段完整且唯一，也无法证明不变档或不管控工具变化不新增事件 | 事件仅包含当前唯一受管 Task 及其创建者/受管工具；CLI 与 VIRTUAL_SCREEN_ABILITY 不叠加，ABILITY、A2A、INSIGHT 不影响结果；不变档时不新增事件，下一次实际事件使用最新唯一上下文，END 保留变化前上下文 |
| VM-2 | R-2 / AC-5.2 | 新建、升档、降档后升档、pending 中重新纳管，以及纳管进程死亡打断待输出合并事件场景 | 集成：立即事件顺序与原始原因核对 | 旧版本缺少明确 START/END 动作语义和死亡使旧合并事件失效的机制，无法保证新建/升档立即 START、死亡立即 END 且旧事件不再输出 | 新建/升档不经过合并窗口即输出 START 并区分前后台与负载原因；死亡立即输出 END，旧合并事件输出计数为 0，其他 pid 不受影响 |
| VM-3 | R-3 / AC-5.3 | 连续升降档、主动注销、正常结束、超时、创建者死亡、继续降档和窗口到期交错场景 | 集成：固定窗口时序 + 最新唯一状态和原始原因核对 | 旧版本在降档和结束时直接输出占位日志，窗口内无法重算最新状态，可能输出旧档位、旧上下文或重复事件 | 窗口前无对应事件；1000ms 到期仅输出一次最新降档 START 或最终 END，无旧档位/旧上下文；无变化时新增事件计数为 0，且不读取策略/窗口系统参数 |
| VM-4 | R-4 / AC-5.4 | 最后一个受管 Task 或其唯一归因被移除、最终 END 后重新纳管、纳管进程死亡、其他 pid 并存，以及既有活动任务和归因上限兼容场景 | 集成：最终生命周期、其他 pid 隔离和既有上限回归 | 旧版本以多任务降档验证为主，无法证明最后移除只有一个最终 END、旧生命周期无后续事件以及重新纳管开启新生命周期，也无法证明既有上限行为不变 | 最后移除仅输出一个最终 END，旧生命周期无后续 START/END；重新纳管允许立即 START；死亡 pid 只有一个最终 END，其他 pid 不受影响；无新增配额/超限拒绝/错误码，既有上限行为与改动前一致 |

**统一集成入口：** 以本节系统场景、hidumper/hilog 和真实接口审计结果为准，单元测试构建与运行证据归 design.md 管理。
