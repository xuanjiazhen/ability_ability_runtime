### 原始描述

**原始问题：** 在 OpenHarmony 系统中，常驻进程（KeepAlive/Resident Process）会在系统启动时自动拉起，以提供持续的服务能力。然而，某些场景下用户希望常驻进程能够按需启动，而非系统启动时自动拉起，以节省系统资源或满足特定业务需求。

**痛点：**

| 用户类型 | 当前痛点 | 影响 |
|----------|----------|------|
| 系统管理员 | 无法控制常驻进程的启动时机 | 系统启动时资源占用高 |
| 系统开发者 | 缺少配置接口控制常驻进程行为 | 无法按需优化系统资源 |

**期望结果：** 提供配置接口，允许设置常驻应用为"按需启动"模式，按需启动模式下，常驻进程在系统启动时不会被自动拉起。

### 问题陈述

在 OpenHarmony 系统中，常驻进程会在系统启动时自动拉起，无法控制其启动时机。需要提供配置接口，允许将常驻应用设置为"按需启动"模式，使常驻进程在系统启动时不被自动拉起，以节省系统资源。

### 目标和成功指标

| 目标 | 成功指标 | 验证方式 |
|------|----------|----------|
| 支持按需启动配置 | 命令执行成功率 100% | 功能测试 |
| 配置持久化 | 重启后配置生效 | 集成测试 |
| 权限控制 | 非授权调用被拒绝 | 安全测试 |

### 用户故事与 AC

| Story ID | 用户故事 | 优先级 |
|----------|----------|--------|
| US-1 | 作为系统管理员，我想要通过命令行工具设置常驻应用的按需启动模式，以便控制系统资源占用 | P0 |
| US-2 | 作为系统开发者，我想要设置为按需启动的常驻进程在系统启动时不被自动拉起，以便减少启动时的资源占用 | P0 |
| US-3 | 作为系统管理员，我想要批量配置多个常驻应用的按需启动模式，以便提高管理效率 | P1 |

| AC编号 | 验收标准 | 类型 | 关联Story |
|--------|----------|------|-----------|
| AC-1.1 | WHEN 执行 `aa set-on-demand -b <bundle> -e 1` THEN 系统保存配置并返回成功 | 正常 | US-1 |
| AC-1.2 | WHEN 执行 `aa set-on-demand -b <bundle> -e 0` THEN 系统取消按需启动配置并返回成功 | 正常 | US-1 |
| AC-1.3 | WHEN 提供无效参数（如空包名或非0/1值）THEN 系统返回参数错误 | 异常 | US-1 |
| AC-1.4 | WHEN 非授权用户执行命令 THEN 系统返回权限拒绝错误 | 异常 | US-1 |
| AC-2.1 | WHEN 系统启动时检查常驻进程列表 THEN 跳过已配置为按需启动的应用 | 正常 | US-2 |
| AC-2.2 | WHEN 未配置按需启动的常驻应用 THEN 系统正常启动该应用 | 正常 | US-2 |
| AC-2.3 | WHEN 配置持久化存储 THEN 重启系统后配置仍然生效 | 正常 | US-2 |
| AC-3.1 | WHEN 系统服务批量设置配置 THEN 所有配置原子性写入数据库 | 正常 | US-3 |
| AC-3.2 | WHEN 批量配置部分失败 THEN 系统返回具体的失败项信息 | 异常 | US-3 |

- 设置常驻应用为按需启动模式的 IPC 接口
