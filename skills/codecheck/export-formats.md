# 原始与专项产物格式

本文件只负责最终证据的呈现，不启动检查、不定义独立 scanner。九阶段主流程完成后才读所需小节；所有产物取自经过反证及历史过滤的同一记录。

沿用原交付约定：统一报告使用 [原模板](codecheck_report_TEMPLATE.md)；逻辑问题详细清单、输入 Excel、API Markdown+CSV 等原始产物继续按对应专项/范围交付，安全 Excel 在用户要求时生成。无适用面不凭空多产附件。用户使用旧 scanner 名称时，按 [公约](conventions.md) §8 映射为检查重点与相同输出类型。

## 安全与高影响问题

### 发现模板（保留原字段；交付项仅 Confirmed）

```text
标题：
位置：file:line（多处调用全部列出）
优先级：P0/P1/P2/P3
证据等级：Confirmed/Likely/Suspicious
bug 视角：
  结果影响：
  触发条件：
  影响范围：
  根本原因：
security 视角：
  审计维度：A/B/C/D/E/F
  G 类编号：（如命中）
同类排查结果：当前影响范围内逐处验证的同根因 file:line 清单及搜索边界
证据：
推荐修复：
推荐测试：
```

触发路径应具体：
```text
通过 API Y，给定输入 X，代码路径 Z 可导致结果 R。
```

### Excel 输出（当请求 Excel 时）

| 列 | 表头 | 说明 |
|----|------|------|
| A | 文件路径 | 相对路径 |
| B | 行号 | 如 `41`、`157-158` |
| C | 问题概述 | 一句话（≤50 字符） |
| D | 问题详细描述 | `### 问题描述` + `### 修复建议` + `### 影响` |
| E | 问题类型 | 内存安全/整数安全/并发安全/输入验证/状态污染/资源泄漏/逻辑缺陷/初始化安全/错误处理/封装违反/信息泄漏/权限安全 |
| F | 风险等级 | 致命/严重/一般/提示 |

样式：表头深蓝底（`4472C4`）白字加粗；数据行 Calibri 11pt 自动换行垂直顶对齐；细边框；列宽 A=55 B=12 C=45 D=90 E=15 F=10；冻结首行；按 风险等级降序后文件路径排序。

保留原发现模板字段，交付项只填 Confirmed；G 类编号有可核实来源才填，否则“—”。bug/security 是同一发现的视角，不重复计数。

Excel 用 [generate_report.py](scripts/generate_report.py)；原六列、文件名和执行中的列宽/样式不变。仅传入最终过滤过的发现，字符串按文本写入。

## 逻辑问题详细分析

每条逻辑问题包含以下字段：位置（file:line）、问题描述、当前代码片段、影响、修复建议、严重等级（🔴 致命 / 🟠 严重 / 🟡 警告 / 🟢 建议）。变更概览（变更文件/类型/影响范围评估）、影响分析（直接/间接/风险评估）、修复优先级分组作为附加上下文一并产出。

保留 🔴/🟠/🟡/🟢 对应 P0/P1/P2/P3；实际定级遵循公约，不能把风格或猜测作为 🟢 输出。

## 外部输入风险清单

### Excel 风险清单


使用 `.xlsx` 文件，工作簿名称 `外部输入风险清单`，必须包含以下列：

| 列名 | 内容要求 |
|------|---------|
| `文件路径` | 问题所在源文件的相对路径 |
| `行号` | `123` 或 `120-130` |
| `链路ID` | 如 `CHAIN-001` |
| `问题概述` | 一句话标题 |
| `外部输入源` | IPC/Parcel / HTTP / CLI / 配置文件 / socket |
| `持久化目标` | DB表 / 文件路径 / 缓存key / 日志 |
| `校验状态` | ❌无校验 / ⚠️部分校验 / ✅充分校验 |
| `攻击面` | 可能的攻击类型 |
| `写入侧评估` | 写入路径防护情况 |
| `读取侧评估` | 读取路径防护情况 |
| `恢复机制` | 恢复能力评估 |
| `风险等级` | P0 / P1 / P2 / P3 |
| `修复建议` | 具体、可操作的修复方案 |

**样式规范**：
- 首行表头：深蓝底（`4472C4`）白字，居中加粗
- 所有单元格：细边框，自动换行，垂直顶对齐
- `风险等级` 列按等级着色：P0=红色（`FF0000`）、P1=浅红（`FF7F7F`）、P2=橙色（`FFC000`）、P3=黄色（`FFFF00`）
- 冻结首行
- 列宽参考：文件路径 50、行号 12、链路ID 14、问题概述 40、外部输入源 18、持久化目标 30、校验状态 12、攻击面 25、写入侧评估 40、读取侧评估 40、恢复机制 40、风险等级 10、修复建议 50


风险等级依公约 §7 的实际后果填写，不能因“无校验/无事务/无恢复”计数定级。保留原工作簿名、十三列、样式与 P0–P3。只导出最终确认且未接受的发现；写 XLSX 字符串时显式设置 `cell.data_type = 's'`，不更改显示内容或列结构。

## API 审计视图

原“第一轮/第二轮/第三轮”表示框架契约、服务实现、测试覆盖三个呈现视角，同一主流程收集其证据，不是三次扫描、测试或 refute。API 专项范围内的接口清单用于各表覆盖，缺项不能默认一致。

测试评级沿用 A/B/C/D：A=必要场景均有有效断言；B=主路径完整、部分必要边界/失败场景欠缺；C=仅部分主路径；D=必要场景几乎无有效覆盖。测试不可得填“未评估”，不虚构百分比或运行结果。测试补充 P0/P1/P2 表示补充优先级，与统一缺陷等级分开；已接受建议不得借覆盖评价重提。

**扫描结果列自包含要求（最高优先级）**：单元格内容必须独立可读——读者只看这一格就能理解问题位置、触发条件、影响、修复方向。**禁止**只写编号引用（如 `❌ H1+H2`），必须复述完整 file:line + 问题描述 + 影响。编号可作前缀索引但必须紧接完整描述。

**编号约定**：R1 高危 H1/H2…、中危 M1/M2…、低危 L1/L2…；R2 服务侧加 `S-` 前缀；R3 测试缺失用 `T-P0-N`/`T-P1-N`/`T-P2-N`。编号仅用于汇总章节排序检索，**不能代替描述**。

### CSV 宽表

默认写到 `<cwd>/<kit-name>_api_audit.csv`。UTF-8，逗号分隔，**所有字段用双引号包裹**。

**15 列结构**：
```
文件,接口,类型,系统API,起始版本,资料描述,R1_扫描结果,R1_修复方案,R2_深度扫描结果,R2_修复方案,R3_正常值覆盖,R3_奇异值覆盖,R3_缺失场景,R3_评级,R3_推荐补充用例
```

**数据合并规则**：以 R1 为 master 列表（CSV 行数 = R1 API 总数）。R2/R3 按 API 名精确匹配或分组匹配合并；未检查的 API 填“未检查”，经核实无对应服务侧/测试面才填 N/A 并解释；不能用缺行默认推断 `✅ 一致`。

**字段清洗**：去除 Markdown 标记（`**`/`` ` ``/`<br>`）；换行转空格；file:line 证据完整保留。字段内双引号由 CSV writer 转义，传入脚本前不要手动转义第二遍；NUL 等控制字符由脚本可见化。**编号引用必须完整展开**（与上文自包含要求一致，禁止只搬编号或“同前/同上”）。

**抽样验证**：CSV 生成后从实际存在的正常行、缺陷行、缺失行和分组行中抽样核对合并；不足 5 行则全检，不为抽样配额编造结果。

**MD 是权威源，CSV 是 MD 的派生视图**。
