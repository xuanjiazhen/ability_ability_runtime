# Codecheck — 九阶段统一检视

先读 [conventions.md](../conventions.md)。全程由一个主流程维护同一份意图、影响链、候选与证据记录；逻辑分析贯穿始终，安全、输入和 API 检查按实际行为加入同一条链。无需分派四个 scanner、生成四套中间结论或重复取证。

保留以下九个处理步骤。步骤 5 的扩搜按证据触发；无适用面时记录理由并继续，不为走完流程制造工作。步骤 4–7 发现的新证据可以回填前序记录，但共用预算。报告中的 Scanner/维度标识是兼容原格式的分类，不表示独立执行者。

## 1. 固定 PR head/base 与历史

固定实际 PR head、diff base、变更文件和目标构建/版本；核对工作目录。无法 checkout 时读 Git 对象或隔离副本，不污染用户工作区。读取已有交付、接受与重开依据，提前跳过未实质改变的已接受点位。

内部记录版本与范围、意图来源、原契约、影响链/待验证假设、候选与排除依据、知识 SHA、测试/refute 次数和历史键，不新增公开报告字段。默认一次定向验证、至多一次必要补充；全流程最多两轮集中 refute。

**完成依据**：比较对象可核实，或明确哪些基准仍不可得；历史可追溯，不能将未知当“未提醒”或“已接受”。

## 2. 获取意图与既有契约

由主流程在深度检视前回答：修改希望得到什么行为？哪些现有保证仍须保持？后续取证发现矛盾时回填，不能把需求解释交给独立 API 检查后再拼接。

证据优先取 PR 描述、关联 Issue/需求与维护者澄清，再看提交消息、目标版本资料、现有调用方和测试。分别标明显式目标、推断目标、原有契约、未知点；不能从“补丁做了什么”循环论证“就应该这样做”。

GitCode 获取路径（只读；逐页取完，区分空结果与访问失败）：
- `GET https://api.gitcode.com/api/v5/repos/{owner}/{repo}/pulls/{number}`
- 同 PR 路径下 `/files`、`/commits`、`/comments`，使用 `page`/`per_page`。
- **关联 Issue**：同 PR 路径下 `/issues`，再用 `/repos/{owner}/{repo}/issues/{issue_number}` 与其 `/comments` 读取内容。PR 正文未写 IssueNo 不等于未关联。
- 补查正文/提交/评论中的明确 Issue 链接；不要仅按标题猜关联，不扫描无关组织数据。API 不可用可读页面或本地已取得材料，并说明来源/限制。
- 官方关联 API：[文档](https://docs.gitcode.com/docs/apis/get-api-v-5-repos-owner-repo-pulls-number-issues/)。鉴权信息不写入 URL、报告或日志。

Issue 可能只有标题，不能当完整需求。缺失意图通常可继续检视旧契约和确定行为；仅当未知业务选择会改变结论且现有来源无法解答时向用户提问，继续不依赖答案的检查。

**完成依据**：区分显式目标、推断目标、必须保留的保障和未知点；未知业务选择若影响结论，先继续不依赖它的检查。

## 3. 建立影响链与所需维度

从变更函数、字段和返回值出发，用全仓符号搜索找调用者、被调用者、共享读写者、异步生产/消费、对象销毁及错误恢复路径；记录“改前 → 改后 → 受影响消费者”及其契约。逻辑、状态、错误传播贯穿整条链。

在同一记录中标出信任、生命周期、线程、IPC、持久化、发布版本等边界。按公约 §8 确定需证明的维度，每一项关联到实际行为与路径，不按文件目录分派扫描。Tier/热点用于决定优先取证的位置。

**完成依据**：每个实质变更都有初始影响链、必要维度与待求证边界；这只是搜索模型，不预先认定问题。

## 4. 按需查知识并统一检视

通过 [知识入口](../patterns/INDEX.md) 每次固定一次知识 SHA，只读当前行为需要的条款。沿同一条影响链检查以下问题，复用已经读过的代码、防护和证据：

| 实际行为/边界 | 加入本条链的检查 |
|---|---|
| 所有变更 | 目标是否实现；状态不变量、错误传播、旧消费者和失败恢复是否保持；读真实分支，不能从函数名推断副作用 |
| 对象、回调、共享资源 | 持有/释放、取消/销毁后的访问、线程同步与真实时序；有共享成员不等于存在竞争 |
| 身份、权限、敏感数据 | 入口控制者、授权主体与对象绑定、IPC/SA 中转及跨用户/设备身份；UI 点击/回调/死亡通知是否真能证明授权或状态完成 |
| 外部输入到 sink | 反向追到可控字段，再向前验证校验/解析、写入、实际读取消费与恢复；参数化 SQL、封装和受限类型可能已提供保障 |
| 对外接口/协议 | 比对目标版本资料、声明、真实实现及旧调用方；输入/输出、错误码、同步异步、生命周期、权限和副作用是否偏移 |

对任一候选连续保存契约、具体路径、防护、后果、最小修复及证据空缺，不在维度交界处停止。候选只有一份；重叠视角仅补证据，不另开一条。

领域追问必须回到当前代码：常规安装与 OTA/预置升级是否走相同事件路径；调试/取消等分支是否只跳过局部计时或真正改变后续流程；查询是否隐含缓存复用或状态修改；资源上限约束单元素还是整个请求/递归/队列。历史经验仅提供线索。

输入链不能按 DB/文件/缓存/日志直接定级；无显式校验、事务或 checksum 不是通用缺陷。注入需证明实际解释语义及后果，`realpath`、加锁或留存原始敏感输入不是默认修复。

接口实现按导出注册、绑定签名及 BUILD.gn/安装目标定位；区分 Stage/FA 同名模块，实际读取匹配版本的 docs、d.ts/.h、NDK 声明，并追到必要服务端点。PR 只覆盖受影响 API；明确指定全 Kit 则从导出清单逐项覆盖相关调用链。找不到关键资料/端点时说明限制，不能填“一致”。

格式在此步骤依公约 §2.1 用项目配置 check-only，结果记入原报告第 5 节，不增加缺陷条目。

**完成依据**：已检查行为有代码/契约依据；候选和不成立的假设可追溯，待扩搜问题具体。

## 5. 针对假设二次扩搜

新增入口可达、共享状态新读写方、跨线程/进程/生命周期、跨版本数据、原防护绕过或消费者契约改变，是继续扩搜的证据。每次写明假设、搜索范围及需要什么证据才能结束，再回步骤 4 验证新增路径。

不固定只查几层，也不因关键词命中多而逐文件全库审计。对同根因/调用族搜索所有受影响点位并逐处验证，语法相似不能直接确认为缺陷。无新边界、证明闭合、假设被反证或关键资料不可得时停止扩搜；后者记录限制，不继续无目标搜索。

**完成依据**：每个扩搜假设已有结论或明确限制；无扩搜必要也允许结束本步。

## 6. 同类合并与定向测试

按根因与稳定点位合并，多个视角引用同一候选；同一行不同根因保持独立。再次排除已接受点位，不把它们放进测试建议或附录。

测试场景从本次行为与影响链生成：变化后的成功路径、真正影响分支的边界、旧消费者、生命周期、失败恢复，以及实际存在的并发/权限/版本边界。为必要场景确定前提、输入/时序、期望输出/状态及有效断言；不作参数笛卡尔积，不要求所有接口都有并发/持久化场景。

先读现有本地 UT/集成/XTS 等适用测试，按需运行最小相关测试或隔离临时用例。没有 XTS 不代表无测试；仅调用 API、mock 恒成功或断言未观察目标行为不等于覆盖。按明确的业务契约核对测试期望。

默认一轮定向验证，仅对改变判定的缺口补充一轮；静态证明充分时不强求复现，无新证据不重跑。单独缺测试通常是覆盖限制/补充建议，不自动成为代码缺陷。测试建议同样历史去重。

**完成依据**：每个候选具备契约—触发—后果—必要修复证据，或明确仍待证；测试覆盖、实际执行结果与未运行项分清。

## 7. 集中双向 Refute

按 [refute-rules.md](refute-rules.md) 反查同一份候选及证据：全部拟交付项基础核验，P0/P1 完整追踪；反查防护是否已消除问题，影响是否夸大或被低估，以及根因是否重复。

最多两轮，第二轮只处理实质争议或新增关键证据。新线索回到步骤 4–6 定向验证，沿用剩余验证预算，不重新启动流程或为每个视角再给两轮。仅能在充分证据下维持、推翻、升降级或合并；待证项不包装为 P3。

**完成依据**：拟交付项证据闭合；剩余未知项退出发现集合，必要维度尚未完成则明确记录。

## 8. 历史过滤后定级与门禁

交付前再次按稳定身份过滤历史，按已证明的后果/条件/范围统一定级。Tier/热点不自动加减级。用 [review_policy.py](../scripts/review_policy.py) 计算确认且去重后的计数、评分、门禁；格式和测试补充建议不计分。

按实际已查路径核实 `dimensions_executed`，同一次取证可覆盖多个维度，但不能因为主流程走完就宣称所有维度已完成。只保留原 schema 1.0 标识；一条问题可有多个视角，仍只扣一次分。

**完成依据**：发现、建议、维度限制与历史状态一致；P0 阻断，缺维度 insufficient，P1 conditional，其余 approve，按公约规定的优先顺序执行。

## 9. 原格式报告与交付历史

按 [原模板](../codecheck_report_TEMPLATE.md) 输出统一报告；使用 [导出格式](../export-formats.md) 的适用章节保留原始清单、专项 Markdown/CSV/XLSX，统一从同一最终证据记录生成。输出视图不触发第二次扫描。`refute_log.md` 记录实际反证，不含已接受问题。

核对所有产物发现一致、已接受点位没有泄漏到摘要/附件/扣分；文本导出依公约防公式注入。零发现仍交代实际覆盖、知识来源、格式与测试限制，不补找问题。原六节、表列、卡片五要素和 YAML 字段不变。

实际交付后才登记本轮提醒；同一轮多个文件只记一次，草稿/重生成不计。无法证实已交付则不增加次数。主流程串行写历史，保留下一轮复用所需的稳定身份和接受/重开依据。

**完成依据**：交付件可追溯到同一最终记录，报告格式与门禁一致，历史只反映实际交付。
