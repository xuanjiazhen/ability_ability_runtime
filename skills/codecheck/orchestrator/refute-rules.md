# Refuter 质疑规则与判定标准

遵循 [公约](../conventions.md) §13：每笔 PR 最多两轮集中 refute，所有检查视角共享限制。BDA 双向审查既排除误报，也核实被低估的影响；不按标签升降级。

## 1. 轮次与停止条件

首轮对全部拟交付候选检查契约、可达路径、影响和重复项，P0/P1 完整追踪关键前提与防护。第二轮仅处理实质争议或新关键证据，不能重复同一论证。没有候选可直接结束；预算耗尽仍不闭合的项留为内部待证。不为每个检查视角单独分配轮次，或因回到取证步骤重置预算。

## 2. 四层证据复核

1. **触发路径**：条件能否同时成立？上游 guard 是否覆盖所有入口、实际构建和时序？权限受限、DEBUG 或 helper 名称均不是自动不可达证据。
2. **实际后果**：沿真实控制/数据流复核崩溃、资源损失、状态错误或边界突破。日志读取仍可能发生 UAF；只写一次的 bool 仍需查线程同步；小上限影响范围而不是自动免责。缺少一条真实后果就不能保留原高等级。
3. **根因与重复**：同根因多表现合并、同类点位一次列全；同一行的独立问题不合并。合并后只扣一次分，保留来源 ID。
4. **低估与组合**：补查已经有证据的外部入口、关键资产、恢复失败和传播范围；按新增事实重新定级。组合链需逐环节及条件可共存的证据，不从越界直接推断 RCE，不因为两个模式同现而宣称成链。

维持、推翻、升降级均指出具体代码或契约依据。**举证责任始终在发现提出者**：缺少关键前提就应撤出正式发现，不要求反驳方证明所有可能路径不可达；“很难触发”也不足以推翻已证实路径。新发现线索回到主流程步骤 4–6，在剩余预算内验证；反证步骤不直接新增正式条目。

已接受点位不进入此附件；被反证的新候选可简记验证依据，避免长篇重复原报告。下述结构沿用原附件形式，所有数字填实测值；无数据写未统计，不照抄示例。

## 4. 交付前一致性

原始发现清单与正式报告只保留最终 Confirmed 项；附件的推翻项不计分。历史过滤在本附件同样生效，不能借“反证/观察”再次提醒已经接受的问题。未运行的测试明确注明，不把推演当运行记录。
