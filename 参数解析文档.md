# 参数解析文档

## 文档概述

本文档详细说明 OpenHarmony CliTool 参数映射系统的实现原理、使用方法和最佳实践。参数映射系统负责将抽象的参数对象转换为具体的命令行参数，是连接高层调用与底层可执行工具的核心桥梁。

**版本**: 1.0.0
**适用范围**: OpenHarmony Ability Runtime CliTool 组件
**参考规范**: `final-config.md`

---

## 1. 系统架构

### 1.1 核心组件

参数映射系统由以下核心组件构成：

```
┌─────────────────────────────────────────────────────────┐
│                    参数映射系统                          │
├─────────────────────────────────────────────────────────┤
│                                                           │
│  ┌─────────────┐      ┌──────────────┐                 │
│  │   调用方     │ ───> │ MapperFactory│                 │
│  │ (参数对象)   │      │  (映射器工厂) │                 │
│  └─────────────┘      └──────┬───────┘                 │
│                              │                           │
│                              ▼                           │
│                    ┌──────────────────┐                 │
│                    │  ArgumentMapper  │                 │
│                    │    (抽象基类)     │                 │
│                    └────────┬─────────┘                 │
│                             │                            │
│           ┌─────────────────┼─────────────────┐         │
│           │                 │                 │         │
│           ▼                 ▼                 ▼         │
│  ┌────────────┐   ┌─────────────┐   ┌─────────────┐   │
│  │ FlagMapper │   │Positional   │   │ Flattened   │   │
│  │ (标志模式)  │   │Mapper       │   │ Mapper      │   │
│  └────────────┘   │(位置模式)    │   │(展平模式)    │   │
│                   └─────────────┘   └─────────────┘   │
│           ┌─────────────┐   ┌─────────────┐           │
│           │JsonString   │   │MixedMapper  │           │
│           │Mapper       │   │(混合模式)   │           │
│           │(JSON模式)   │   └─────────────┘           │
│           └─────────────┘                              │
│                              │                           │
│                              ▼                           │
│                     ┌───────────────┐                  │
│                     │ argv[1...n]   │                  │
│                     │(命令行参数)   │                  │
│                     └───────────────┘                  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 职责划分

| 组件 | 职责 | 不负责 |
|------|------|--------|
| `input` | 定义参数类型、结构、必填项和约束 | 参数如何映射到命令行 |
| `argumentMapping` | 定义参数到命令行的转换方式 | 参数类型定义和校验 |
| `MapperFactory` | 根据映射类型创建对应的映射器实例 | 具体的映射逻辑实现 |
| `ArgumentMapper` | 实现具体的参数映射逻辑 | 参数的合法性校验 |

## 2. 映射类型详解

### 2.1 概述

系统支持 5 种映射类型，每种类型适用于不同的场景：

| 映射类型 | 典型输出 | 适用场景 | 复杂度 |
|---------|----------|----------|--------|
| `flag` | `--key=value`, `-v` | 标准 CLI 工具 | 低 |
| `positional` | `arg1 arg2 arg3` | 传统 Unix 风格工具 | 低 |
| `flattened` | `--app-name=value` | 嵌套配置对象 | 中 |
| `json-string` | `--config='{"k":"v"}'` | 复杂结构传递 | 中 |
| `mixed` | 组合多种模式 | 复合型 CLI 工具 | 高 |

### 2.2 选择决策树

```
                    ┌─────────────────┐
                    │   参数结构？     │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
        简单标量          嵌套对象          复杂组合
            │                │                │
            ▼                ▼                ▼
    ┌───────────────┐ ┌─────────────┐ ┌─────────────┐
    │需要固定顺序？  │ │需要路径展平？│ │    ┌─────┐  │
    └───────┬───────┘ └──────┬──────┘ │    │ mixed│  │
            │                │       └─────┴─────┘  │
       是/否              是/否                       │
       │  │               │  │                       │
       ▼  ▼               ▼  ▼                       │
   positional  flag   flattened  json-string         │
                                                      │
                         所有情况 ────────────────────┘
```

## 3. Flag 模式

### 3.1 设计理念

Flag 模式遵循 POSIX 和 GNU 风格的命令行参数约定，是最常见的参数映射方式。

**核心特征**：
- 每个参数都显式携带参数名
- 支持短选项（`-v`）和长选项（`--verbose`）
- 布尔值支持条件开关

### 3.2 配置结构

```json
{
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "<字段名>": "<模板字符串>",
      "<布尔字段>": {
        "if_true": "<真值模板>",
        "if_false": "<假值模板>"
      }
    }
  }
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"flag"` |
| `templates` | object | 是 | 参数模板映射表 |
| `templates.<field>` | string/object | 是 | 字段模板，字符串或布尔对象 |
| `templates.<field>.if_true` | string | 条件必填 | 布尔真值时的模板 |
| `templates.<field>.if_false` | string | 条件必填 | 布尔假值时的模板 |

### 3.3 处理规则

#### 3.3.1 标量类型

**String 类型**：
```json
{
  "input": {
    "properties": {
      "target": {"type": "string"}
    }
  },
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "target": "--target={value}"
    }
  }
}
```

**输入**: `{"target": "192.168.1.1"}`
**输出**: `["--target=192.168.1.1"]`

**Number/Integer 类型**：
```json
{
  "input": {
    "properties": {
      "timeout": {"type": "integer"}
    }
  },
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "timeout": "--timeout={value}"
    }
  }
}
```

**输入**: `{"timeout": 30}`
**输出**: `["--timeout=30"]`

#### 3.3.2 Boolean 类型

**方式一：字符串模板**：
```json
{
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "verbose": "--verbose={value}"
    }
  }
}
```

**输入**: `{"verbose": true}`
**输出**: `["--verbose=true"]`

**方式二：条件开关（推荐）**：
```json
{
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "verbose": {
        "if_true": "-v",
        "if_false": ""
      }
    }
  }
}
```

**输入**: `{"verbose": true}` → `["-v"]`
**输入**: `{"verbose": false}` → `[]`（空输出被跳过）

#### 3.3.3 Array 类型

数组会展开为多个同名参数：

```json
{
  "input": {
    "properties": {
      "ports": {
        "type": "array",
        "items": {"type": "integer"}
      }
    }
  },
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "ports": "--port={value}"
    }
  }
}
```

**输入**: `{"ports": [80, 443, 8080]}`
**输出**: `["--port=80", "--port=443", "--port=8080"]`

#### 3.3.4 Object 类型限制

Object 类型**不支持**直接在 flag 模式中使用，应改用 `flattened` 或 `json-string`：

```json
// ❌ 错误示例
{
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "config": "--config={value}"  // config 是 object 类型，会报错
    }
  }
}

// ✅ 正确做法：使用 json-string
{
  "argumentMapping": {
    "type": "json-string",
    "templates": {
      "config": "--config={value}"
    }
  }
}
```

### 3.4 完整示例

**网络扫描工具**：

```json
{
  "name": "ohos-netscan",
  "version": "1.0.0",
  "description": "Network scanning utility",
  "executable": "/system/bin/cli_tool/executable/ohos-netscan",
  "input": {
    "type": "object",
    "properties": {
      "target": {
        "type": "string",
        "format": "ipv4",
        "description": "Target IP address"
      },
      "ports": {
        "type": "array",
        "items": {"type": "integer", "minimum": 1, "maximum": 65535},
        "description": "Ports to scan"
      },
      "timeout": {
        "type": "integer",
        "minimum": 1,
        "maximum": 300,
        "default": 5
      },
      "verbose": {
        "type": "boolean",
        "default": false
      }
    },
    "required": ["target"]
  },
  "argumentMapping": {
    "type": "flag",
    "templates": {
      "target": "--target={value}",
      "ports": "--port={value}",
      "timeout": "--timeout={value}",
      "verbose": {
        "if_true": "-v",
        "if_false": ""
      }
    }
  }
}
```

**测试输入**：
```json
{
  "target": "192.168.1.1",
  "ports": [80, 443],
  "timeout": 10,
  "verbose": true
}
```

**生成的命令**：
```bash
/system/bin/cli_tool/executable/ohos-netscan --target=192.168.1.1 --port=80 --port=443 --timeout=10 -v
```

### 3.5 最佳实践

1. **布尔参数优先使用条件开关**：`if_true`/`if_false` 比字符串模板更语义化
2. **数组参数使用复数形式命名**：`ports` 而非 `port`
3. **必填参数放在前面**：便于阅读和调试
4. **使用标准前缀**：长选项用 `--`，短选项用 `-`

## 4. Positional 模式

### 4.1 设计理念

Positional 模式模拟传统 Unix 命令的参数传递方式，参数按固定顺序排列，不携带参数名。

**核心特征**：
- 参数位置固定，含义由位置决定
- 输出简洁，适合参数较少的场景
- 不支持复杂结构（数组、对象）

### 4.2 配置结构

```json
{
  "argumentMapping": {
    "type": "positional",
    "order": ["<字段1>", "<字段2>", "..."]
  }
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"positional"` |
| `order` | string[] | 是 | 参数顺序列表，定义字段输出顺序 |

### 4.3 处理规则

#### 4.3.1 类型转换

所有非字符串类型统一转换为字符串：

| 输入类型 | 输出示例 | 说明 |
|---------|---------|------|
| `string` | `"file.txt"` | 原样输出 |
| `number` | `"3.14"` | 转为字符串 |
| `integer` | `"42"` | 转为字符串 |
| `boolean` | `"true"` / `"false"` | 固定格式 |

#### 4.3.2 不支持的类型

```json
// ❌ 错误示例
{
  "input": {
    "properties": {
      "files": {"type": "array"},      // 数组不支持
      "config": {"type": "object"}     // 对象不支持
    }
  },
  "argumentMapping": {
    "type": "positional",
    "order": ["files", "config"]       // 会报错
  }
}
```

### 4.4 完整示例

**文件复制工具**：

```json
{
  "name": "ohos-copy",
  "version": "1.0.0",
  "description": "File copy utility",
  "executable": "/system/bin/cli_tool/executable/ohos-copy",
  "input": {
    "type": "object",
    "properties": {
      "source": {
        "type": "string",
        "description": "Source file path"
      },
      "destination": {
        "type": "string",
        "description": "Destination file path"
      },
      "verbose": {
        "type": "boolean",
        "description": "Enable verbose output",
        "default": false
      }
    },
    "required": ["source", "destination"]
  },
  "argumentMapping": {
    "type": "positional",
    "order": ["source", "destination", "verbose"]
  }
}
```

**测试输入**：
```json
{
  "source": "/data/file.txt",
  "destination": "/backup/file.txt",
  "verbose": true
}
```

**生成的命令**：
```bash
/system/bin/cli_tool/executable/ohos-copy /data/file.txt /backup/file.txt true
```

### 4.5 使用场景

Positional 模式适用于：

1. **参数含义明确**：`cp source dest` 不需要参数名也能理解
2. **参数数量少**：通常不超过 3 个
3. **传统工具兼容**：模拟已有 Unix 工具的行为

**不适合场景**：

- 参数较多（超过 5 个）
- 有可选参数
- 参数类型复杂（数组、对象）

## 5. Flattened 模式

### 5.1 设计理念

Flattened 模式用于处理嵌套对象配置，将多层级的对象结构"展平"为路径形式的参数。

**核心特征**：
- 支持嵌套对象的路径提取
- 自定义分隔符（`.`、`_`、`-`）
- 保留布尔值条件开关支持

### 5.2 配置结构

```json
{
  "argumentMapping": {
    "type": "flattened",
    "separator": ".",
    "templates": {
      "<路径>.<字段>": "<模板>"
    }
  }
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"flattened"` |
| `separator` | string | 否 | 路径分隔符，默认为 `.`，支持 `.`, `_`, `-` |
| `templates` | object | 是 | 路径模板映射表 |
| `templates.<path>` | string/object | 是 | 路径模板 |

### 5.3 路径解析

#### 5.3.1 基本路径

```json
{
  "input": {
    "properties": {
      "server": {
        "type": "object",
        "properties": {
          "host": {"type": "string"},
          "port": {"type": "integer"}
        }
      }
    }
  },
  "argumentMapping": {
    "type": "flattened",
    "separator": ".",
    "templates": {
      "server.host": "--host={value}",
      "server.port": "--port={value}"
    }
  }
}
```

**输入**：
```json
{
  "server": {
    "host": "192.168.1.100",
    "port": 8080
  }
}
```

**输出**：
```json
["--host=192.168.1.100", "--port=8080"]
```

#### 5.3.2 深层嵌套

```json
{
  "input": {
    "properties": {
      "app": {
        "type": "object",
        "properties": {
          "env": {
            "type": "object",
            "properties": {
              "production": {"type": "boolean"}
            }
          }
        }
      }
    }
  },
  "argumentMapping": {
    "type": "flattened",
    "templates": {
      "app.env.production": {
        "if_true": "--env-prod",
        "if_false": ""
      }
    }
  }
}
```

**输入**：
```json
{
  "app": {
    "env": {
      "production": true
    }
  }
}
```

**输出**：
```json
["--env-prod"]
```

### 5.4 分隔符选择

| 分隔符 | 适用场景 | 示例 |
|-------|---------|------|
| `.` | 通用场景，符合编程习惯 | `server.host` |
| `_` | 避免与文件路径混淆 | `server_host` |
| `-` | 符合 CLI 风格 | `server-host` |

**示例**：

```json
{
  "argumentMapping": {
    "type": "flattened",
    "separator": "_",
    "templates": {
      "db_config_host": "--db-host={value}",
      "db_config_port": "--db-port={value}"
    }
  }
}
```

### 5.5 约束规则

1. **路径必须有效**：路径中的每个节点都必须是 `object` 类型
2. **叶子节点不能是数组**：数组类型不支持 flattened
3. **叶子节点不能是对象**：必须展开到具体字段
4. **路径不能重复**：同一字段不能被多个路径引用

### 5.6 完整示例

**应用部署工具**：

```json
{
  "name": "ohos-deploy",
  "version": "1.0.0",
  "description": "Application deployment utility",
  "executable": "/system/bin/cli_tool/executable/ohos-deploy",
  "input": {
    "type": "object",
    "properties": {
      "app": {
        "type": "object",
        "properties": {
          "name": {"type": "string"},
          "replicas": {"type": "integer"},
          "env": {
            "type": "object",
            "properties": {
              "production": {"type": "boolean"},
              "region": {"type": "string"}
            }
          }
        }
      },
      "server": {
        "type": "object",
        "properties": {
          "host": {"type": "string"},
          "port": {"type": "integer"},
          "tls": {
            "type": "object",
            "properties": {
              "enabled": {"type": "boolean"},
              "certPath": {"type": "string"}
            }
          }
        }
      }
    },
    "required": ["app"]
  },
  "argumentMapping": {
    "type": "flattened",
    "separator": ".",
    "templates": {
      "app.name": "--app-name={value}",
      "app.replicas": "--replicas={value}",
      "app.env.production": {
        "if_true": "--env-prod",
        "if_false": "--env-dev"
      },
      "app.env.region": "--region={value}",
      "server.host": "--host={value}",
      "server.port": "--port={value}",
      "server.tls.enabled": "--tls={value}",
      "server.tls.certPath": "--cert={value}"
    }
  }
}
```

**测试输入**：
```json
{
  "app": {
    "name": "webapp",
    "replicas": 3,
    "env": {
      "production": true,
      "region": "us-west-1"
    }
  },
  "server": {
    "host": "api.example.com",
    "port": 443,
    "tls": {
      "enabled": true,
      "certPath": "/etc/tls/cert.pem"
    }
  }
}
```

**生成的命令**：
```bash
/system/bin/cli_tool/executable/ohos-deploy \
  --app-name=webapp \
  --replicas=3 \
  --env-prod \
  --region=us-west-1 \
  --host=api.example.com \
  --port=443 \
  --tls=true \
  --cert=/etc/tls/cert.pem
```

## 6. JSON-String 模式

### 6.1 设计理念

JSON-String 模式用于将复杂结构（对象、数组）序列化为 JSON 字符串后传递给命令行工具。

**核心特征**：
- 保留原始数据结构
- 一次性传递整个配置
- 适合复杂嵌套场景

### 6.2 配置结构

```json
{
  "argumentMapping": {
    "type": "json-string",
    "templates": {
      "<字段名>": "<模板字符串>"
    }
  }
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"json-string"` |
| `templates` | object | 是 | 参数模板映射表 |
| `templates.<field>` | string/object | 是 | 字段模板 |

### 6.3 处理规则

#### 6.3.1 标量类型

标量类型会直接转为字符串：

```json
{
  "argumentMapping": {
    "type": "json-string",
    "templates": {
      "mode": "--mode={value}",
      "count": "--count={value}"
    }
  }
}
```

**输入**: `{"mode": "deploy", "count": 3}`
**输出**: `["--mode=deploy", "--count=3"]`

#### 6.3.2 Object 类型

对象会被序列化为 JSON：

```json
{
  "input": {
    "properties": {
      "config": {
        "type": "object",
        "properties": {
          "cpu": {"type": "string"},
          "memory": {"type": "string"}
        }
      }
    }
  },
  "argumentMapping": {
    "type": "json-string",
    "templates": {
      "config": "--config={value}"
    }
  }
}
```

**输入**：
```json
{
  "config": {
    "cpu": "2",
    "memory": "4Gi"
  }
}
```

**输出**：
```json
["--config={\"cpu\":\"2\",\"memory\":\"4Gi\"}"]
```

**实际命令**：
```bash
tool --config='{"cpu":"2","memory":"4Gi"}'
```

#### 6.3.3 Array 类型

数组同样会被序列化：

```json
{
  "input": {
    "properties": {
      "tags": {
        "type": "array",
        "items": {"type": "string"}
      }
    }
  },
  "argumentMapping": {
    "type": "json-string",
    "templates": {
      "tags": "--tags={value}"
    }
  }
}
```

**输入**: `{"tags": ["v1", "production", "stable"]}`
**输出**: `["--tags=[\"v1\",\"production\",\"stable\"]"]`

#### 6.3.4 Boolean 类型

支持两种方式：

**方式一：字符串模板**
```json
{
  "templates": {
    "verbose": "--verbose={value}"
  }
}
```
**输入**: `{"verbose": true}`
**输出**: `["--verbose=true"]`

**方式二：条件开关**
```json
{
  "templates": {
    "verbose": {
      "if_true": "--verbose",
      "if_false": ""
    }
  }
}
```
**输入**: `{"verbose": true}`
**输出**: `["--verbose"]`

### 6.4 约束规则

1. **对象和数组只能使用字符串模板**：不支持 `if_true`/`if_false`
2. **布尔值可以使用两种方式**：字符串模板或条件开关
3. **模板必须包含 `{value}`**：标量类型的字符串模板必须包含占位符

## 7. Mixed 模式

### 7.1 设计理念

Mixed 模式是组合器，允许在一个工具中同时使用多种映射模式。它不是新的底层编码方式，而是对已有四种模式的灵活组合。

**核心特征**：
- 复用已有映射模式，不引入新规则
- 灵活处理复杂 CLI 工具
- 保证输出顺序稳定

### 7.2 配置结构

```json
{
  "argumentMapping": {
    "type": "mixed",
    "mappings": {
      "<参数名>": {
        "mode": "flag|positional|flattened|json-string",
        "template": "...",
        "separator": ".",
        "order": 1
      }
    }
  }
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 固定为 `"mixed"` |
| `mappings` | object | 是 | 参数映射表 |
| `mappings.<param>.mode` | string | 是 | 映射模式 |
| `mappings.<param>.template` | string/object | 条件必填 | 模板（flag/json-string/flattened 需要） |
| `mappings.<param>.separator` | string | 否 | 分隔符（仅 flattened 使用） |
| `mappings.<param>.order` | integer | 条件必填 | 顺序（仅 positional 使用） |

### 7.3 各子模式配置

#### 7.3.1 Positional 子模式

```json
{
  "action": {
    "mode": "positional",
    "order": 1
  }
}
```

**规则**：
- 必须指定 `order`，且为正整数
- 不允许指定 `template`、`separator`
- 不同字段的 `order` 不能重复

#### 7.3.2 Flag 子模式

```json
{
  "verbose": {
    "mode": "flag",
    "template": {
      "if_true": "--verbose",
      "if_false": ""
    }
  },
  "timeout": {
    "mode": "flag",
    "template": "--timeout={value}"
  }
}
```

**规则**：
- 必须指定 `template`
- `template` 可以是字符串或布尔对象
- 不允许指定 `separator`、`order`

#### 7.3.3 Flattened 子模式

```json
{
  "server": {
    "mode": "flattened",
    "template": {
      "server.host": "--host={value}",
      "server.port": "--port={value}"
    },
    "separator": "."
  }
}
```

**规则**：
- 必须指定非空 object 类型的 `template`
- `template` 中的所有路径 key 必须以参数名为根
- `separator` 可选，默认为 `.`，支持 `.`, `_`, `-`
- 不允许指定 `order`

#### 7.3.4 JSON-String 子模式

```json
{
  "config": {
    "mode": "json-string",
    "template": "--config={value}"
  }
}
```

**规则**：
- 必须指定 `template`
- `template` 必须是字符串（不能是布尔对象）
- 不允许指定 `separator`、`order`

### 7.4 输出顺序

为保证输出稳定，mixed 采用以下顺序规则：

1. **第一阶段**：所有 `mode = positional` 的条目按 `order` 升序输出
2. **第二阶段**：其余条目按 `mappings` 中的书写顺序输出

**示例**：

```json
{
  "argumentMapping": {
    "type": "mixed",
    "mappings": {
      "verbose": {"mode": "flag", "template": "-v"},
      "action": {"mode": "positional", "order": 2},
      "service": {"mode": "positional", "order": 1},
      "config": {"mode": "json-string", "template": "--config={value}"}
    }
  }
}
```

**输出顺序**：`service` (order=1) → `action` (order=2) → `verbose` → `config`

### 7.5 约束规则

#### 7.5.1 字段不重复消费

同一字段不能被多个映射条目引用：

```json
// ❌ 错误示例
{
  "mappings": {
    "server": {
      "mode": "flattened",
      "template": {
        "server.host": "--host={value}",
        "server.port": "--port={value}"
      }
    },
    "server_host": {
      "mode": "flag",
      "template": "--server-host={value}"
    }
  }
}
// server.host 会被两个条目重复消费
```

#### 7.5.2 Positional order 不重复

```json
// ❌ 错误示例
{
  "mappings": {
    "action": {"mode": "positional", "order": 1},
    "target": {"mode": "positional", "order": 1}
  }
}
// order = 1 重复，会报错
```

#### 7.5.3 Flattened 路径根节点

```json
// ❌ 错误示例
{
  "mappings": {
    "server": {
      "mode": "flattened",
      "template": {
        "db.host": "--db-host={value}"  // 路径根节点是 "db"，不是 "server"
      }
    }
  }
}
```

```json
// ✅ 正确示例
{
  "mappings": {
    "server": {
      "mode": "flattened",
      "template": {
        "server.db.host": "--db-host={value}"  // 路径以 "server" 为根
      }
    }
  }
}
```

## 8. 输入验证

### 8.1 Schema 验证

参数映射系统基于 JSON Schema 子集实现输入验证。

#### 8.1.1 支持的类型

| 类型 | 约束字段 | 示例 |
|------|---------|------|
| `string` | minLength, maxLength, pattern, format | IP地址、邮箱 |
| `number` | minimum, maximum, exclusiveMinimum, exclusiveMaximum, multipleOf | 采样比例 |
| `integer` | 同 number，但值必须是整数 | 端口号、计数 |
| `boolean` | default | 开关标记 |
| `array` | items, minItems, maxItems, uniqueItems | 端口列表 |
| `object` | properties, required | 配置对象 |

#### 8.1.2 Format 支持

| Format | 说明 | 示例 |
|--------|------|------|
| `ipv4` | IPv4 地址 | `192.168.1.1` |
| `ipv6` | IPv6 地址 | `2001:db8::1` |
| `hostname` | 主机名 | `example.com` |
| `email` | 邮箱地址 | `user@example.com` |
| `uri` | URI | `https://example.com` |
| `date` | RFC 3339 日期 | `2023-01-01` |
| `date-time` | RFC 3339 日期时间 | `2023-01-01T00:00:00Z` |

### 8.2 验证流程

```python
from mapper import validate_input, MapperFactory

# 1. 定义 Schema
schema = {
    "type": "object",
    "properties": {
        "target": {
            "type": "string",
            "format": "ipv4",
            "minLength": 7,
            "maxLength": 15
        },
        "ports": {
            "type": "array",
            "items": {"type": "integer", "minimum": 1, "maximum": 65535},
            "minItems": 1,
            "uniqueItems": True
        }
    },
    "required": ["target"]
}

# 2. 准备输入
input_args = {
    "target": "192.168.1.1",
    "ports": [80, 443]
}

# 3. 验证输入
is_valid, errors = validate_input(input_args, schema)

if not is_valid:
    print("验证失败:", errors)
    exit(1)

# 4. 执行映射
mapper = MapperFactory.create(mapping_config)
argv = mapper.map(input_args)
```

### 8.3 常见错误

| 错误类型 | 示例 | 解决方案 |
|---------|------|---------|
| 类型不匹配 | `"age": "25"` 应为 integer | 检查字段类型 |
| 缺少必填字段 | 缺少 `target` | 补充必填字段 |
| 约束违反 | `ports: [0]` 小于 minimum | 调整值或约束 |
| 格式错误 | `"email": "invalid"` | 修正格式 |

## 9. 最佳实践

### 9.1 映射模式选择

**决策树**：

```
参数结构？
├─ 简单标量
│  ├─ 需要固定顺序？ → positional
│  └─ 不需要 → flag
├─ 嵌套对象
│  ├─ 需要路径展平？ → flattened
│  └─ 需要保持结构 → json-string
└─ 复杂组合 → mixed
```

### 9.2 命名约定

**字段命名**：
- 使用驼峰命名法：`serverHost` 或 `server.host`
- 布尔值使用疑问词：`verbose`、`enabled`、`dryRun`
- 数组使用复数：`ports`、`tags`、`items`

**模板命名**：
- 长选项使用 `--`：`--target`
- 短选项使用 `-`：`-v`、`-f`
- 组合选项使用 `-`：`--dry-run`、`--app-name`

### 9.3 布尔值处理

**推荐方式**：使用 `if_true`/`if_false`

```json
{
  "verbose": {
    "if_true": "--verbose",
    "if_false": ""
  }
}
```

**不推荐**：字符串模板

```json
{
  "verbose": "--verbose={value}"  // 会生成 --verbose=true
}
```

### 9.4 复杂配置组织

**优先级**：
1. 简单场景：flag
2. 嵌套配置：flattened
3. 复杂结构：json-string
4. 复合场景：mixed

**示例**：

```json
{
  "argumentMapping": {
    "type": "mixed",
    "mappings": {
      "action": {"mode": "positional", "order": 1},
      "target": {"mode": "positional", "order": 2},
      "verbose": {"mode": "flag", "template": {"if_true": "-v", "if_false": ""}},
      "server": {
        "mode": "flattened",
        "template": {"server.host": "--host={value}"},
        "separator": "."
      },
      "config": {"mode": "json-string", "template": "--config={value}"}
    }
  }
}
```

### 9.5 错误处理

**验证顺序**：
1. JSON 格式验证
2. Schema 结构验证
3. 参数类型验证
4. 约束条件验证
5. 映射配置验证

**错误提示**：
```python
try:
    mapper = MapperFactory.create(mapping_config)
    argv = mapper.map(input_args)
except ValueError as e:
    print(f"配置错误: {e}")
except KeyError as e:
    print(f"缺少字段: {e}")
except Exception as e:
    print(f"映射失败: {e}")
```

## 10. 性能考虑

### 10.1 性能指标

| 操作 | 平均耗时 | 说明 |
|------|---------|------|
| Schema 验证 | < 1ms | 简单配置 |
| 创建映射器 | < 0.1ms | MapperFactory |
| 参数映射 | < 1ms | 10个参数以内 |
| JSON 序列化 | < 0.5ms | json-string 模式 |

### 10.2 优化建议

1. **缓存映射器实例**：相同配置可以复用
   ```python
   # 不推荐
   for args in arg_list:
       mapper = MapperFactory.create(config)
       argv = mapper.map(args)

   # 推荐
   mapper = MapperFactory.create(config)
   for args in arg_list:
       argv = mapper.map(args)
   ```

2. **延迟验证**：先验证再映射
   ```python
   is_valid, errors = validate_input(args, schema)
   if not is_valid:
       return errors  # 提前返回
   argv = mapper.map(args)  # 验证通过后才映射
   ```

3. **避免不必要的复杂配置**：
   - 简单场景用 flag，不要用 mixed
   - 小配置用 flattened，不要用 json-string

   ```json
   }
   ```

2. **union 类型**：联合类型
   ```json
   {
     "source": {
       "oneOf": [
         {"type": "string"},
         {"type": "object"}
       ]
     }
   }
   ```
